It took way too long (4 years) but the rewrite is finally done. Thank you for your patience!

[Play Store](https://play.google.com/store/apps/details?id=com.ikcode.ancientstar1)  
[itch.io](https://iktools.itch.io/ancient-star)

So what is new? Brand new look, more or less, sounds, music, and animation. The new framework made it much easier to integrate multimedia for negligible performance cost. The old “framework”, raw canvas drawing, was straining weaker devices if there were too many shapes to draw. It’s like polygon count issues for 3D hardware accelerated games but instead of million polygons per frame we are talking a few hundreds of curves per frame. Nebulas were supposed to be made of 50 up and down curves and had to scale it back to flat lines. In the new framework the curves are back because it’s all one image so whatever is drawn on it costs the same. Similar story for fleet paths, they were a dashed line before to save on shape count and now are animated arrows clearly conveying the direction.

There are also some bug fixes and minor new features that also got ported to the old framework version. Mass orders in the diplomacy screen come to mind. One reason for this is that more than half of the code is actually shared between the two versions. The game code is designed around MVC (model-view-controller) architecture where game logic (with computer player) lives in one module that is used by other user interface modules. Initially the idea was to use it for a multiplayer server if I ever come to that but it became useful much sooner. The remaining view code was easy to make with AI.

About AI. Very little was made using it. By the time LLM coding agents became available more than 75% of the rewrite had been already made and I still had to learn how to use it. So the remaining 25% ended up being 95% hand written. Where the AI was most useful was with debugging and with build scripts. It is surprisingly good at finding out a root cause of a bug but the same can’t be said about letting it fix it. The capacity of the rabbit hole maze it is capable of digging is amazing! Build scripts are a different story, they are undocumented arcane spells that no living person can master. Accepting unnatural help there is lesser evil, trust me.

On a serious note, adding one button with AI to the old framework is exactly why I started the rewrite with LibGDX. It became mentally unbearable to make more UI in it. “Mass orders” are not just one button, there is a dialog for picking a template colony, plumbing for opening and closing dialog, and the dialog has a scrollable list that should be backed by a recycler view, item view holder, and list adapter. Honestly, over the years I’ve forgotten the ins and outs of such a needlessly complicated system. I knew roughly how the solution should look but I’d still have to spend the entire week relearning details and verifying my assumptions every step of the way. It was not worth it so it was either no button or AI made one. With AI I skipped the pain and only made the final verification. But even when my Android XML views skill was fresh it was a pain to make the UI look right. Espionage is actually halfway done already but has no UI to access it. In the dev build there is a placeholder button for sending a spy to a foreign colony and infiltrator flight, infiltration roll and spy network maintenance do work.

What LibGDX offers, among many other benefits, is multiplatform builds. This is great for reaching a wider audience but is also a huge development improvement. Reruning a desktop build after a code change is very fast and is much more convenient to iterate and troubleshoot than mobile builds (either on device or emulator). The UI part of the framework is simpler to work with so I can add more UI for the same amount of effort. And UI and game graphics live in the same “space”, I’m free to mix and match them any way I want. Before it was a hassle to draw fleet size text next to fleet location triangle or to add star image in event report list. Maybe one day I’ll make colony controls right on the map without the side panel.

So what is next? I’d like to finish the espionage. It was planned for v4.0 but rewrite alone ate all of the scope. I always thought that gathering intelligence was an integral part of a genre that got implemented wrong almost every time. By espionage I don’t mean a hidden dice that you roll in hopes to copy other’s technology or to blow up a building that actually matters. What I mean is gathering information that you can’t see directly. Like scouting with fallible stealth, and gradual subterfuge like sabotage and rebellions in Master of Orion 1. I don’t know, that’s my hunch that I’d like to test with an experiment.

Survival mode on the other hand is a failed experiment. It was not as purposeful as I imagined it would be. The original idea was even more miserable, you had to wait until all of your colonies were destroyed and thanks to player feedback I redesigned it to end after a certain percentage got lost. But there are more options for improvement, that’s where the experiment has succeeded. I’ll try some of them at some point and see how it goes.

Space combat could be better. I don’t want it to be a blind numbers game it is now. Effectively types are meaningless. Sure there is rock-scissors-paper relation between individual types but that finesse ends with fleets containing them in 1:1:1 ratio. I want to make it relevant when and where you deploy each type. Also, I’d like to change how movement works so ships have to spend time at stars where combat happens. And also also I’d like to introduce a retreat mechanic which would act as attrition damage to doom stacks. That last one needs more time in the oven. I’m on the cusp of formulating it. But I do know exactly what to do with movement, let all star to star jumps run with the same speed and move “slow” and “fast” star concepts to cooldown time between jumps. Do you like the idea or should I make it togglable?

Ground combat could be much better. The current system is a copy of Master of Orion’s method without the dice roll. Like espionage it’s one of the genre’s mechanics that are lacking but I haven’t had the idea and courage to challenge it. My gut feeling is that it should work over multiple turns and be more like applied pressure than poured acid. Again, I have some ideas on paper that need to be organized into a coherent whole.

Story campaign is something I’d like to see in the genre. So many games have rich lore but only as background fluff or as a tutorial. I know it costs a lot to make, especially if you don’t bound the ambition level but it could pay off as a force that binds players together. In anycase I have a few story beats on the paper, a few characters, and you are already introduced to the factions. And at the very end it is a kind of work that can be a slow burner in between other changes,  visible only in a dev build.

And there is a laundry list of fluff and minor mechanics that are now possible with easier graphics and UI implementation: player emblems, terraforming, megastructures, more star types, more detailed star systems. I know that’s all hopes and promises but I finally feel lighter when I think about them, they are all possible now.
